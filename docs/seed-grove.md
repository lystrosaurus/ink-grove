# Seed Grove 实装边界与验收

Seed Grove 是与 Ink Grove 共用内核的儿童认知花园。首版取自[原设计](<design/Seed Grove｜小小思考家儿童底层认知系统设计文档.md>) §45–46，当前保留四个区域、六个 Seed、Think 8、家长提示、简单成长记录和响应式体验。原设计保持原文；本文面向后续开发与验收，功能、契约或入口变化时同步更新。

## 2026-09-13 设计调整：统一体验

按用户最新要求，1.3.0 取消 Seed 的年龄分组，并在 Ink 顶部导航和首页提供清楚可见的 Seed 入口。孩子进入地图后直接选择感兴趣的问题，不先选择年龄，也不换成全局难度档；两套产品继续保留各自的导航、视觉语言和数据。

每个 Seed 提供一份连贯的活动：用简短、具体的情境提出问题，允许动手尝试并看到反馈，最后带走一个现实生活中的问题。「再想一步」提供可自由尝试的延伸，不设年龄门槛、解锁条件或能力判断。Think 8 同样使用统一情境与可选延伸。这样能保留探索深度，也避免靠隐藏年龄参数继续分流内容。

此调整替代原设计中的年龄版本要求，仅更新维护中的实现约定；`docs/design/` 与 `materials/*.html` 保留原字节。旧的带年龄参数链接仍可打开，但进入的是统一活动；当前 manifest、导航与新内容不再以年龄选择资源。

## One Core, Two Experiences

共享机制应减少重复的安全与数据处理，同时让两套产品各自表达。现有 React + Vite + JavaScript + CSS 可以承载这一边界；原设计中的 Next.js、TypeScript 等是技术建议，本版沿用仓库已有技术栈。

| 边界     | 共用部分                                             | 各产品负责                                                        |
| -------- | ---------------------------------------------------- | ----------------------------------------------------------------- |
| 内容     | 稳定 ID、manifest、Renderer 与本地资源的基本契约     | Ink 的作品、集合与概念；Seed 的区域、统一活动、思考问题与家长提示 |
| 展示     | HTML 沙箱、Markdown/SVG/图片的安全呈现、构建时通信桥 | 各自导航、阅读器外壳、语言、密度和互动方式；作品内部保留独立视觉  |
| 数据     | JSON 校验接入点、原始恢复保护与保存失败处理          | 各自 schema、存储键、事件含义和冲突交互，不合并备份               |
| 分发     | 同一 Vite 构建、静态资源和 CloudBase 发布流程        | `/` 与 `/seed` 入口及各自样式                                     |
| 后续能力 | Ink 已有且默认关闭的 AI provider 接口                | 无 Seed 自由聊天；Journey、Graph 等按真实需求逐步接入             |

Ink 的探索、阅读、创作与知识连接继续保留。Seed 的首页是可探索的成长地图，作品是可操作的认知体验；孩子不需要先学成人概念，也不需要填写能力分数。

实现分为四个可独立核验的切片：

1. 共用内核：`app/src/core/` 承接 Renderer 与 JSON 存储保护，Ink 保留自身包装与数据契约；先用原有 Ink 流程验证行为兼容。
2. 内容构建：`content/seeds/` 与 `scripts/build-seeds.mjs` 生成独立目录，核验六个 Seed 的资源、来源、统一活动与延伸问题。
3. 儿童体验：`app/src/seed/SeedApp.jsx`、`seed.css` 和 `questions.js` 提供地图、玩法、Think 8 与家长入口，通过实际浏览器验证独立的视觉和交互。
4. 本地闭环：`app/src/seed/garden.js` 绑定 Seed 权威目录，接上显式成长记录和数据管理，验证成功、失败、恢复与跨标签页冲突。

## 当前内容与入口

区域沿用原设计的层号，不把未交付的六层显示成已可体验的内容。

| 区域                 | 层号 | Seed ID                                  |
| -------------------- | ---- | ---------------------------------------- |
| 看见自己／内心花园   | 1    | `emotion-weather`、`attention-detective` |
| 理解选择／选择路口   | 2    | `time-store`                             |
| 学会学习／学习山谷   | 4    | `just-right-challenge`、`break-it-down`  |
| 理解反馈／反馈实验室 | 5    | `mistakes-are-clues`                     |

六个 Seed 各自保留独立玩法与视觉表达。统一体验不是将历史年龄版依次堆在一页，而是围绕一个问题组织情境、可操作的尝试、反馈和现实行动；「再想一步」在同一问题上增加观察、因果或权衡。不要求所有 Seed 使用同一文章排版。

| 路由                                 | 可验证行为                                               |
| ------------------------------------ | -------------------------------------------------------- |
| `/`                                  | 从 Ink 顶部导航或首页邀请进入 Seed                        |
| `/seed`                              | 进入独立首页地图，自由选择四个区域                       |
| `/seed/layer/:id`                    | 显示该区域的 Seed，打开具体体验                          |
| `/seed/play/:slug`                   | 展示统一 HTML 活动与可选延伸，提供家长提示和手动记录入口 |
| `/seed/think`                        | 显示 Think 8 八张问题卡                                  |
| `/seed/think/q1` 至 `/seed/think/q8` | 各有简短情境与可操作的思考，不只是静态口号               |
| `/seed/parent`                       | 查看陪伴提示，使用本地备份与数据管理                     |
| `/seed/growth`                       | 查看由用户明确添加的发现与现实使用记录                   |

这些是应用 History 路由，直接访问和刷新都需进入对应页面。`/seeds/` 是生成的作品资源目录，与 `/seed` 应用路由区分；静态发布后的 HTTP 200 不足以证明资源已正确部署。

## 内容来源与生成

`content/seeds/<id>/manifest.json` 是每个 Seed 的权威元数据，`content/seed-catalog.json` 提供 Seed ID 索引及四个区域，构建输出 `app/src/generated/seed-catalog.json` 时重新读取完整 manifest。Think 8 的短互动保存在 `app/src/seed/questions.js`。不要把 Seed 加进 Ink 的 `content/catalog.json`；当前 Seed 以统一活动资源、思考问题、家长提示和真实来源描述内容，不新增年龄元数据或年龄版资源选择。

Seed 没有用户提供的原始 HTML 时，允许围绕原设计创作独立的故事或互动，provenance 标明 AI 辅助创作和真实设计来源。共享“反馈”等概念不构成来自《控制论》或其他成人作品的派生证据；只有实际使用了该作品才记录该来源与关系。

`scripts/build-seeds.mjs` 验证并生成 Seed 内容，复用 `scripts/build-content.mjs` 的 HTML 展示适配。生成目录是 `app/src/generated/` 和 `app/public/seeds/`；修改 manifest 或内容源后运行 `npm run content`，发布用 `npm run build` 生成两套体验的同一份 `app/dist`。构建必须拒绝无效标识、越界资源、不符合统一体验契约的元数据和不存在的关系目标。

HTML 仍通过 `sandbox="allow-scripts"` 呈现，不放开同源、弹窗、表单或顶层导航。iframe 消息验证来源窗口，外部参考只请求父页展示，用户确认固定目标后打开；详细约定见 [AGENTS.md](../AGENTS.md)。

## 本地数据与成长语义

Seed 继续使用 `seed-grove:garden:v1`，以便发现既有记录；键名中的 `v1` 不代表当前数据格式。Ink 继续使用 `ink-grove:garden:v1`；同域分发不会使两者共享花园数据或备份。当前 Seed 数据包括 `schemaVersion: 2`、`product: "seed-grove"`、`revision` 和 `events`，花园和事件均不含年龄字段。导入时校验版本、产品身份及具体字段，拒绝未知字段和重复记录，不能把 Ink 备份当 Seed 备份覆盖。

每个成长事件恰好关联一个 Seed 或一个 Think 8 问题，保留记录 ID、`kind`（`discovery`／`real-life`）、文字、`source`（`child`／`parent`）与 ISO 时间；最多 1000 条，每条文字最多 600 个字符，备份最多 1 MB。记录引用必须存在于 Seed 目录或 `q1`–`q8`，不接受成人作品引用、年龄或能力评分字段。

1.2 的 `schemaVersion: 1` 数据与备份仍可读取：先按旧契约严格校验，包括旧花园与事件的合法年龄字段，再在内存中移除年龄并转换为 v2。转换保留事件 ID、关联目标、记录含义、文字、来源、发生时间与 revision；加载本身不自动写入浏览器存储。下次用户明确保存且存储成功后才持久化 v2，新导出直接使用 v2。有效旧备份在预览并确认后恢复为 v2；损坏、未知版本或字段非法的旧数据仍保留原始恢复保护，不能因兼容迁移而放宽校验或清空记录。

成长记录只表达发生过的事：孩子或家长明确记下“有一个新发现”，或明确记录“在现实生活里用过”。打开 Seed、点击选项和滚动到底不自动生成能力结论；次数也不转换为聪明值、排行榜或“已掌握”标签。家长提示帮助陪伴观察，不提供诊断或儿童性格分析。

所有记录留在当前浏览器。导出、恢复和删除由用户操作；恢复先校验并预览确认，写入成功后才更新界面。保存失败要保留当前状态并提示；损坏或未知版本数据先保护原始副本，可下载恢复数据；跨标签页更新须检测冲突，避免静默覆盖。没有账号、云同步、在线模型调用或儿童输入上传。

Seed 的本地记录是用户报告，不能证明孩子已经在生活中形成稳定能力。复杂成长推断、十层完整内容、十二个 Seed 的完整首批清单、长期 Journey、儿童画像和跨产品概念桥仍属后续范围。

## 验收切片

每一切片同时检查用户看到的结果与失败时的数据边界。下表是验收标准，执行结果以对应测试和发布验收记录为准，不把测试未覆盖的长期成长效果写成已实现。

| 切片       | 关键验收                                                                                                   |
| ---------- | ---------------------------------------------------------------------------------------------------------- |
| 两套入口   | Ink 顶部与首页可进入 Seed；直接打开和刷新两套路由；Seed 不出现成人书架导航；桌面和手机没有横向溢出         |
| 内容完整性 | 四区六 Seed、Think 8 可达；没有年龄或全局难度选择；统一活动与延伸问题可用；正文和封面可读取               |
| 独立互动   | 六 Seed 的操作会产生可理解的结果或反馈；Think 8 每张卡能尝试；延伸自由可达；无点击即“已掌握”的评价         |
| 渲染安全   | HTML 保持受限沙箱；伪造窗口消息不生效；外部参考需父页点击确认；原素材和设计文档字节未变                    |
| 本地闭环   | 手动新增发现与现实使用，刷新仍可见；导出后恢复、取消恢复、删除均有明确行为；Ink 数据不变                   |
| 旧版兼容   | 有效 v1 记录只读迁移且语义与时间不变；加载不回写；显式保存或恢复成功后写 v2；新备份无年龄字段             |
| 异常保护   | 错误产品／版本／损坏备份拒绝覆盖；配额或存储失败不显示保存成功；冲突不静默丢失；原始恢复数据可导出         |
| 发布       | 对同一份产物做本机生产检查，再用 CloudBase `--safe --verify` 发布；公网验证 `/seed` 深链接、实际正文和互动 |

内容与模型测试执行 `npm test`，浏览器验证执行 `npm run test:e2e`，发布前执行 `npm run build` 并检查生产预览。本版执行状态维护在 [1.3 发布验收记录](../artifacts/verification-1.3.json)，[1.2 记录](../artifacts/verification-1.2.json)保留历史验证结果。共用 Renderer 或存储机制变化时同时运行 Ink 回归；操作步骤、CLI 3.8.1 根路径限制和回滚流程统一维护在[部署说明](deployment.md)。
